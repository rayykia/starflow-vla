# STARFlow-VLA — LIBERO World Action Model

Two camera views (agentview + wrist) + instruction + proprio → **next-H-frames two-view
video + H-step action chunk**, generated by a single normalizing flow. The action chunk is one more group in the deep block's
autoregressive sequence: the model first attends the condition tokens and the observation
(i2v-style KV-cache context), then generates the future video, then generates the action
chunk conditioned on that video. Design spec: `docs/superpowers/specs/2026-08-15-starflow-vla-design.md`.

**Conditioning (current):** the flan-T5 text prefix has been replaced by a **SmolVLM**
condition encoder. SmolVLM-500M-Instruct reads the task instruction *and* the current
observation; every output token is linearly projected to the deep-block width and
concatenated with a projected **proprioception** token,
`y = [proj_p(proprio) | proj_v(SmolVLM(obs, instruction))]` (the same construction as
`SimVLANF/models/nf/context_video.py::build_condition`). See §1.1.

All code lives on branch `starflow-vla`. **No upstream STARFlow-V file was modified**
(`transformer_flow.py`, `train.py`, `sample.py`, `dataset.py`, `utils/`, `misc/` are
untouched).

### Architecture in one paragraph

Each camera view's frames are encoded by the frozen **Wan2.2 causal video VAE** as an
independent clip (`[obs; H frames]` → `1 + H/4` latent frames of 48×8×8 at 128px) and the
two views' latents are channel-concatenated (`channel_size = 2 × 48 = 96`; agentview
first), so both views are generated in the same AR tokens. Video latents pass through the upstream
per-frame shallow flow blocks; the normalized action chunk `[H, 7]` passes through its
own small shallow flow (`action_blocks`). The deep block then runs one causal AR flow
over `[condition tokens | video tokens | H action tokens]` — action tokens get their own
input/output projections (7-dim vs 96-dim) and RoPE positions `(0, 0, T_lat + j)`.
Because of the global SOS shift, the output at the last video token predicts the first
action: **the chunk is generated strictly after, and conditioned on, the video**.
Training maximizes exact likelihood; the loss is a per-modality mean
`NLL_video + action_loss_weight · NLL_action` (separate means because action dims are
<1% of the total). Generation: encode condition + obs → `context=True` fills the KV
caches → one deep-block reverse pass emits video then actions → each modality goes
through its own shallow inverse → VAE decode / action un-normalization.

### 1.1 Condition encoder: SmolVLM + proprio (replaces flan-T5)

```
obs agentview + wrist (2,3,128,128) ─ Wan VAE per view, channel-concat ─▶ frame-0 prefix of the video group
obs agentview ───── resize 512 ─▶ SigLIP ─▶ connector ─▶ 64 img tokens ─┐
instruction ────────────────────────── tokenizer ───────────────────────┤ SmolVLM text model (Llama)
                                                                        │ last hidden state (B, L, 960)
proprio (8) ─▶ proprio_proj ─▶ 1 token ─┐                               ▼
                                        └─ concat ◀── vlm_proj ◀── zero padded positions
                                            y (B, 1 + L, channels)  ──▶ deep block prefix (proj_txt = identity)
```

* **Token layout** (`vla/vlm_encoder.py`) mirrors SmolVLM's own chat template for one
  un-split image, so a frozen backbone sees in-distribution input:
  `<|im_start|>User:<fake_token_around_image><global-img>` + 64 image features +
  `<fake_token_around_image>{instruction}<end_of_utterance>\nAssistant:`. The instruction
  suffix is right-padded to `txt_size` tokens (mask passed to the LM; padded outputs zeroed,
  as upstream did for T5). Image features come from
  `vision_model → connector` on the GPU tensor directly (no PIL round trip), exactly like
  `SimVLANF ... forward_vlm_efficient`. `L = 5 + 64 + txt_size`.
* **Proprio** = `[ee_pos(3), ee_ori(3, axis-angle), gripper_states(2)]` from the HDF5 at
  step `t`, z-score-normalized with the `state` mean/std in the norm-stats file
  (`(x - mean) / (std + 1e-6)`, same map as actions). The LIBERO client's `observation/state`
  (`[eef_pos, quat→axis-angle, gripper_qpos]`) has the same layout.
* **Where the projections live:** `WorldActionModel.vlm_proj` (960 → `channels`) and
  `proprio_proj` (8 → `channels`); the deep block's `proj_txt` is replaced by the identity
  (so `txt_dim == channels`). `build_condition(features, proprio)` does the concat;
  `encode_condition(images, instructions, proprio)` runs the VLM first. Training calls
  `model(x, actions=a, cond=dict(images=..., instructions=..., proprio=...))` so the VLM
  and the projections are inside the DDP forward.
* **Classifier-free guidance** drops the *instruction only* (`drop_label` → `""`); the
  null half keeps the observation and the proprio token. Inference builds both halves in
  one VLM pass (`vla.sample_libero.encode_condition`).
* **Frozen vs fine-tuned:** `vlm_freeze: 1` freezes the backbone (no grads, `no_grad`
  forward, eval mode). Default `vlm_freeze: 0` fine-tunes it in its own optimizer group
  (`vlm_lr`, held at 0 for `vlm_freeze_steps` optimizer steps like SimVLANF's
  `freeze_steps`, then the same warmup/cosine shape as the flow). The VLM weights are part
  of the checkpoint either way (`model.vlm.*`, ~1.8 GB fp32), so a `.pth` is a complete policy.
* **Checkpoint compatibility:** checkpoints trained with the T5 condition
  (`logs/libero_model_vla_1024_6_h8.pth*`) cannot be loaded (`proj_txt` / condition width
  differ); they need the pre-switch commit.

### Environment changes (conda env `starflow`)

- Installed: `h5py`, `pytest`, `imageio`, `imageio-ffmpeg`, plus `requirements.txt` deps.
- `transformers` pinned to **4.57.6** (5.x breaks upstream `utils/model_setup.py`).
- torchvision ≥0.23 removed `tv.io.write_video`, so previews use a local imageio
  writer (`save_video_grid`) instead of upstream `save_samples_unified`.
- A stray ROS install pollutes `PYTHONPATH` — prefix commands with `PYTHONPATH= `.
- `flash-attn` must be **2.7.4.post1** (`+cu12torch2.6cxx11abiFALSE`, from the
  Dao-AILab GitHub releases). Every 2.8.x `torch2.6` wheel — including the ones
  labelled `cxx11abiFALSE` — is actually built against the new libstdc++ ABI and
  fails to import under torch 2.6 (`undefined symbol: _ZN3c105ErrorC2E...__cxx11...`).
  Note this only affects the optional `diffusers` attention backend: the model and the
  Wan VAE call `F.scaled_dot_product_attention` directly, so training speed is
  unchanged either way.

## 3. Running training

```bash
# 4-GPU DDP with wandb (recommended entry point; env vars pick GPUs/batch/run name)
bash scripts/train_vla_libero.sh
GPUS=0,4,5,6 BATCH_SIZE=64 RUN_NAME=libero10-h8 bash scripts/train_vla_libero.sh

# single GPU
PYTHONPATH= python vla/train_libero.py --model_config_path configs/starflow_vla_libero_128.yaml

# multi-GPU by hand (DDP; keep fsdp: 0)
PYTHONPATH= torchrun --nproc_per_node=4 vla/train_libero.py \
  --model_config_path configs/starflow_vla_libero_128.yaml

# quick sanity (1 batch, no sampling, no wandb)
PYTHONPATH= python vla/train_libero.py --model_config_path configs/starflow_vla_libero_128.yaml \
  --batch_size 4 --num_workers 0 --sample_freq 0 --dry_run 1 --no_wandb 1
```

`scripts/train_vla_libero.sh` forwards any extra arguments to the trainer, so
`bash scripts/train_vla_libero.sh --lr 5e-5 --action_loss_weight 2.0` works.

Any config key can be overridden on the command line; **CLI wins over the YAML**
(use space-separated `--flag value`; `--flag=value` also works):

```bash
PYTHONPATH= python vla/train_libero.py --model_config_path configs/starflow_vla_libero_128.yaml \
  --batch_size 32 --lr 5e-5 --action_loss_weight 2.0
```

Outputs (under `logs/`):
- `libero_model_vla_<channels>_<blocks>_h<H>.pth` — latest model weights (+ epoch-tagged
  copies every `save_every` epochs), `libero_opt_....pth` — optimizer/LR-schedule state.
- `libero_samples_.../rollout_epochNNNN.mp4` — preview rollouts every `sample_freq`
  epochs, plus a printed `[preview] ... action MAE (normalized)` line (MAE vs clean,
  un-noised ground truth).

WandB (rank 0 only, when a key is available) logs:

| Panel | Keys |
|---|---|
| `train/*` | all five loss terms + `grad_norm`, every `log_every` optimizer steps |
| `epoch/*` | the same terms averaged over the epoch (all-reduced across ranks) |
| `lr`, `epoch` | LR schedule value and fractional epoch |
| `perf/*` | `steps_per_sec`, `samples_per_sec`, `gpu_mem_gb`, `epoch_time_s` |
| `preview/*` | `action_mae_normalized` and the rollout mp4, every `sample_freq` epochs |

Run naming/routing: `--wandb_name`, `--wandb_project`, `--wandb_entity`,
`--wandb_id` (pass the same id to resume a run), `--wandb_env_file`, `--no_wandb 1`.

**Resume:** `--resume_path logs/libero_model_....pth --resume_epoch N` (pair them —
the epoch positions the LR schedule when no optimizer checkpoint exists; when the
optimizer checkpoint is found next to the model one it is loaded automatically).

Memory reference: the default config at `--batch_size 4` peaks ~14.3 GB on one
RTX 4080 SUPER (16 GB). The config's `batch_size: 64` is a *global* batch meant for a
multi-GPU/SLURM setup; divide by world size × `acc` for the per-GPU size.

> **⚠ `grad_skip` silently kills training.** The skip rule is
> `pre-clip grad_norm > grad_clip`, but this model's *healthy* grad norm is ~5.5 while
> `grad_clip` is 1.0 — so with the original `grad_skip: 1` every update after step 100
> was skipped (9,435/9,373 eligible steps in a real 17-epoch run). It is quiet rather
> than loud: the loss simply freezes at whatever it reached by step 100, the epoch
> summary prints with no metrics at all (`metrics.update` only runs on non-skipped
> steps), and the preview action MAE *degrades* (0.481 → 0.535 → 0.576 over epochs
> 6/11/16), because upstream still calls `optimizer.step()` after zeroing the grads,
> so AdamW keeps applying weight decay and momentum. `vla/train_libero.py` now really
> skips the step and thresholds at `grad_clip × grad_skip_factor`.
>
> **Symptom to watch for:** `grep -c 'skipping update'` in the log should be ~0, and
> the loss should keep falling past step 100. Healthy: −0.88 @100 → −1.88 @300.

Measured on 4× A100-80GB (`libero_10`, 138,090 samples/epoch):

| Global batch | Per-GPU | GPU mem | Throughput | Steps/epoch | Epoch time |
|---|---|---|---|---|---|
| 64 | 16 | ~19 GB | 2.10 it/s = 134 samples/s | 2157 | ~17 min |
| 256 | 64 | ~30 GB | 1.30 it/s = 333 samples/s | 539 | ~7 min |

Global batch 256 is ~2.5× the throughput at well under half the card. It also cuts the
optimizer steps per epoch 4×, so `lr: 1e-4` (tuned for batch 64) is likely low for it —
consider 2e-4 (√-scaling) to 4e-4 (linear) if you keep `epochs: 100`.

## 4. Configuration guide

`configs/starflow_vla_libero_128.yaml` is a flat list of `--flag value` pairs fed to
the parser in `vla/train_libero.py` (`get_vla_parser` = upstream tarflow parser + VLA
flags). Edit the YAML or override on the CLI.

### 4.1 Training hyperparameters

| Key | Default | Meaning / how to tune |
|---|---|---|
| `batch_size` | 64 | Global batch. Per-GPU = `batch_size / world_size / acc`. |
| `acc` | 1 | Gradient-accumulation steps. |
| `lr` / `min_lr` | 1e-4 / 1e-6 | Cosine schedule peak / floor; warmup = one epoch unless `warmup_steps` set. |
| `epochs` | 100 | Total epochs. |
| `epoch_length` | 50000 | Samples per "epoch" on single GPU (fresh random draw each epoch). Ignored under DDP (full dataset; a notice is printed). |
| `noise_std` | 0.3 | Gaussian noise added to video latents (flow smoothing). Raising it blurs video but stabilizes likelihood. |
| `action_noise_std` | 0.1 | Dequantization noise on normalized actions — **required** (gripper channel is discrete ±1); lower it if action precision matters more than likelihood stability. |
| `action_loss_weight` | 1.0 | λ on the action NLL term. Increase (e.g. 2–5) to prioritize the policy over video quality. |
| `drop_label` | 0.1 | Text-dropout rate for classifier-free guidance training. |
| `cfg` / `preview_guidance` | 1.5 | Guidance scale used by the CLI sampler / training previews. |
| `grad_clip` / `grad_skip` | 1 / **0** | Clip norm at 1.0; `grad_skip` drops a step whose pre-clip norm exceeds `grad_clip × grad_skip_factor` (after step 100). **Leave `grad_skip` off** — see the warning below. |
| `grad_skip_factor` | 10.0 | Multiplier on `grad_clip` for the skip threshold. Upstream skips at `grad_clip` itself, which is unusable here. |
| `sample_freq` | 5 | Preview rollout every N epochs (0 disables). |
| `save_every` | 10 | Epoch-tagged checkpoint frequency. |
| `num_workers` | 4 | Dataloader workers. |
| `loss_scaling` | 1 | AMP GradScaler on/off. |

### 4.2 Model architecture

| Key | Default | Meaning / constraints |
|---|---|---|
| `channels` | 1024 | Transformer width of all flow blocks. Main scale knob (with `layers_per_block`). |
| `layers_per_block` | `2 2 2 2 2 12` | One entry per flow block; the **last** entry is the deep block, the rest are per-frame shallow blocks. **The count must be even** (so the deep block gets the identity permutation under L2R). Scale up: `2 2 2 2 2 24`; scale down: `2 2 1 8`. |
| `top_block_channels` | (unset = `channels`) | Give the deep block a larger width than the shallow blocks (as the 7B config does with 4096). |
| `head_dim` / `num_heads` / `num_kv_heads` | 64 / auto / auto | Attention geometry; heads default to `channels/head_dim`; set `num_kv_heads < num_heads` for GQA. |
| `channel_size` | 96 | Channels per video token = number of views × VAE latent channels (2 × 48 for Wan2.2). The training loop asserts it against the fused latents. |
| `img_size` | 128 | Pixel resolution. Must be divisible by 16 (Wan2.2 f16). Changing it requires `pt_seq_len = img_size/16` and LIBERO frames are natively 128 — other sizes would need dataset-side resizing. |
| `pt_seq_len` | 8 | Latent grid side = `img_size / 16`. Keep in sync with `img_size`. |
| `txt_size` | 40 | Max SmolVLM tokens for the instruction suffix (instruction + ~6 template tokens; LIBERO instructions are ≤ ~20). A warning is printed if a suffix fills every slot. |
| `vlm` | `HuggingFaceTB/SmolVLM-500M-Instruct` | Condition encoder backbone (any Idefics3/SmolVLM checkpoint with `vision_model` / `connector` / `text_model`; hidden size is picked up automatically, e.g. 2048 for SmolVLM2-2.2B). |
| `vlm_image_size` | 512 | Obs is resized to this for SigLIP; 512 → 64 image tokens, 256 → 16 (cheaper, off the pretraining resolution). |
| `vlm_freeze` | 0 | 1 = frozen backbone (only `vlm_proj` / `proprio_proj` / the flow train). |
| `vlm_lr` | 2e-5 | Peak LR of the VLM parameter group (the flow uses `lr`). SimVLANF fine-tunes at the full head LR; 2e-5 is the conservative default here. |
| `vlm_freeze_steps` | 1000 | VLM LR held at 0 for the first N optimizer steps (grads are still computed), so the randomly initialised flow does not wreck the pretrained features. |
| `proprio_dim` | 8 | `[ee_pos(3), ee_ori(3), gripper_states(2)]`; the `state` entry of the norm-stats file must match. |
| `action_horizon` | 8 | H — number of future frames **and** actions. **Must be divisible by 4** (Wan temporal compression); latent frames = `1 + H/4`. 12 or 16 also work; regenerate nothing, just retrain. |
| `action_dim` | 7 | LIBERO action dimensionality. |
| `action_layers` | `2 2` | Layers per action-shallow-flow block (two blocks, alternating direction). |
| `action_channels` / `action_head_dim` | 256 / 64 | Width/heads of the action shallow blocks (they model 7-dim tokens; keep small). |
| `vae` | `Wan-AI/Wan2.2-TI2V-5B-Diffusers:0.6` | Frozen video VAE; `:0.6` is the temporal latent scale. |
| `gradient_checkpoint` | 0 | Set ≥1 to checkpoint attention every N layers if you scale up and hit memory limits. |

**Invariants asserted in code — do not change:** `sos: 1`, `seq_order: L2R`, even
`len(layers_per_block)`, `cond_top_only: 1` (text enters only at the deep block),
`shallow_block_local: 1` (shallow blocks are per-frame), `action_horizon % 4 == 0`,
and no `local_attn_window` (the KV-cache sizing for action tokens excludes it —
`ActionMetaBlock.upgrade` will assert loudly). `temporal_causal` may be any value >0
(only `==0` is ever tested; the denoiser that would consume its value is disabled).

## 5. Inference / policy use

```bash
PYTHONPATH= python vla/sample_libero.py \
  --model_config_path configs/starflow_vla_libero_128.yaml \
  --checkpoint_path logs/libero_model_vla_1024_6_h8.pth \
  --sample_index 0 --cfg 1.5
```

Prints predicted vs ground-truth action chunks (un-normalized, plus their MAE) and
writes `predict_*.mp4`. `--denoise 1` (default) applies score-based denoising; any
extra `--flag value` overrides the config. Programmatically:

```python
from vla import predict, predict_batch, load_norm_stats, setup_vla_model
model = setup_vla_model(args).to(device)          # builds the SmolVLM encoder too
model.load_state_dict(torch.load(ckpt, map_location='cpu'), strict=True)
norm_stats = load_norm_stats(args.norm_stats)     # {'actions': ..., 'state': ...}
video, action_chunk = predict(model, vae, args, norm_stats, obs_image, instruction,
                              proprio_raw, guidance=1.5, denoise=True)
# obs_image (3, 128, 128) in [-1, 1]; proprio_raw (8,) un-normalized robot state;
# video: (1+H, 3, 128, 128) in [-1, 1]; action_chunk: (H, 7), un-normalized.
out = predict_batch(model, vae, args, norm_stats, obs_images, instructions, proprio_raw,
                    guidance=1.5)                                # (n, 3, 128, 128), n strings, (n, 8)
out['actions']                                                   # (n, H, 7), denoised + un-normalized
```

Closed loop: execute the H actions, observe, call `predict` again. Guidance is
optional (`guidance=0` skips CFG and is cheaper).

**Score-based denoising.** The flow is trained on noisy targets (video latents +
`N(0, noise_std²)`, normalized actions + `N(0, action_noise_std²)`), so a raw sample
lives in that noisy space. `score_denoise` applies one Tweedie step
`x ← x − σ² ∇ₓ NLL(x)` using the exact model likelihood, with σ taken from the training
config (`action_noise_std` for the chunk, `noise_std` for the video; the video is held
fixed when differentiating w.r.t. the actions, which is exact because video tokens
precede action tokens in the AR sequence). On the (T5-conditioned) trained checkpoint,
actions noised with σ = 0.1 recovered to MAE 0.013 from 0.079 (gripper 0.004 from 0.083),
and sampled chunks improved from ~0.15 to ~0.11 normalized MAE vs the demo actions.

**LIBERO benchmark:** `vla/eval_libero/` (server in `nfvla`, simulator clients in the
`libero` env, cross-client batching, sharded launch script, result summarizer) — see
its README.

## 7. Known limitations (v1 scope)

SmolVLM conditions on the agentview only (the wrist view is VAE-encoded into the video
prefix and generated, but not shown to the VLM), one-chunk horizon (no
long-horizon rollout stitching), no Jacobi (parallel) sampling for the action group,
FSDP optimizer-resume not wired (use `fsdp: 0`, the default). AR sampling is
latency-bound (~3 s per call regardless of batch size up to ~16), so evaluation
throughput comes from running many simulator clients against one server. See the
spec's "Out of scope" section.
